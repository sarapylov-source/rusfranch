# Календарь сообщества

Страница: https://www.frgu.ru/calendar.html. Анкета: https://t.me/rusfranch_bot?start=event_add.

## Как работает

1. `/add_event` или сообщение «Добавить событие» в личном диалоге с `rusfranch_bot`.
2. Бот проверяет фактическое членство в чате «Масштаб», включая резидентов и проверенных подрядчиков. Неучастнику предлагает оформить подписку. Ошибка Telegram не считается отсутствием подписки и не открывает доступ.
3. Анкета: название → дата и необязательное время по Москве → онлайн/офлайн → город и площадка для офлайна → бесплатно/платно → целая сумма в рублях → описание → необязательная ссылка → необязательная афиша → подтверждение.
4. Участникам автоматически ставится источник «партнёр». У Семёна и Ярославы перед анкетой есть выбор источника.
5. Заявка попадает в отдельную SQLite и очередь личных уведомлений двум модераторам. До одобрения её нет в публичном JSON и на сайте.
6. Один из двух модераторов одобряет или отклоняет с причиной. При одобрении членство автора проверяется ещё раз. В одной транзакции сохраняются решение и задания на анонс и уведомления. Вторая кнопка одобрения не создаст дубль.
7. Одобренное событие попадает в публичный JSON, затем анонс публикуется в основной группе от бота. Афиша — фото, описание — подпись. Если описание длинное, в подписи краткая версия, полная — в карточке календаря. Ссылка на регистрацию сохраняется.
8. Автор или модератор может отменить событие. Оно исчезает с сайта; под уже опубликованным анонсом бот размещает уведомление об отмене.

## Архитектура

- `events_store.py`: валидация, транзакции SQLite, черновики, аудит, публикационные задания.
- `community_events.py`: адаптер Telegram, middleware и фоновый обработчик в **существующем** `community-listener`.
- `test_events.py`: тесты без реальных отправок и без доступа к боевым базам.
- `../../calendar.html`, `calendar.css`, `calendar.js`: статическая страница, сетка по месяцам, мобильный список, фильтры и диалог события.
- `../../calendar-events.json`: резервный снимок событий сообщества; исходное наполнение базы при установке.

Дополнительного webhook, poller, HTTP API для записи, доступа к Supabase или второго бота нет. Текущие модули привратника, премии, закрытого клуба и вебинаров сохраняются. Middleware календаря перехватывает только свои личные команды, активную анкету и `ev:`-кнопки. Групповые сообщения, вступления, опросы и остальные callbacks проходят дальше.

Рабочие данные: `/opt/bots/community-digest/events.db`, WAL, busy timeout, журнал решений. Доступ 0600. Данные уже входят в существующий ночной `.backup` баз `/opt/bots`; исходный код также входит в серверный архив. Секретов в исходниках и JSON нет.

Публичная проекция: `/var/www/frgu-events/events.json`, афиши — `posters/event-ID.jpg`, Nginx отдаёт `https://api.frgu.ru/events/` только как статические файлы, с CORS и кэшем 30 секунд. В JSON — явный список публичных полей: без ID пользователей, Telegram file_id, причин отказов и внутренней очереди. Афиши скачиваются только после одобрения, проверяются Pillow, уменьшаются и перекодируются в JPEG без исходных метаданных. Файлы заменяются атомарно.

Worker просыпается раз в 2 секунды; экспорт при изменениях — примерно раз в 15 секунд. Браузер обновляет JSON раз в минуту. При недоступности API показывает резервный календарь и явно сообщает, что события партнёров сейчас недоступны. Пустой успешный ответ API считается корректным: отменённые события не восстанавливаются из резервной копии. Прошедшие события доступны при просмотре прошлых дат; главная страница сохраняет свой список будущих событий.

## Защита от сбоев

- Черновик хранится в SQLite; перезапуск не теряет прогресс.
- Блокировка на пользователя, nonce каждого шага, учёт ID входящих сообщений, атомарное решение модератора и уникальный ключ публикационного задания.
- Подтверждённый rate limit Telegram возвращает задание в очередь с указанной задержкой.
- Ошибка прав/невалидные данные → `failed`. Сетевой таймаут/неизвестный результат → `uncertain`. После падения процесса задания `sending` тоже становятся `uncertain`.
- Неопределённую отправку автоматически не повторяем: Bot API не предоставляет ключ идемпотентности для `sendMessage`/`sendPhoto`. Сначала модератор проверяет целевой чат. Это сознательный выбор против дублей; обещать exactly-once через Bot API нельзя.
- Уведомление о проблеме приходит обоим модераторам, сама задача остаётся в базе. `/calendar_admin` показывает незавершённые заявки и ошибки. Если личное уведомление недоступно, задача не пропадает.
- Экспорт JSON идемпотентен и повторяем. Ошибка афиши не скрывает текст события. Проверка номера аудита не позволяет экспорту затереть признак нового решения, принятого во время скачивания картинки.
- Отмена блокируется, пока исход анонса неизвестен: сначала нужно сверить публикацию.

## Команды

- `/add_event` — новая анкета или продолжение сохранённой.
- `/my_events` — статусы и отмена своих событий.
- `/event_cancel` — удалить текущий черновик.
- `/calendar_admin` — очередь модерации и отправки, только Семён/Ярослава.
- `/event_cancel ID` — отменить событие, с подтверждением.
- `/event_retry JOB` — после ручной проверки отсутствия сообщения запросить повтор; требуется подтверждение кнопкой.
- `/event_sent JOB MESSAGE_ID` — подтвердить уже отправленное сообщение. Бот проверяет доступ к указанному сообщению в целевом чате, фиксирует результат; для анонса сохраняет ID сообщения.

## Установка и откат

Используется aiogram из действующего окружения, дополнительная зависимость `Pillow>=11,<13` (установлена 12.3.0). Модули копируются в `/opt/bots/community-digest`. В `listener.py`: импорт, `build` **до** middleware клуба/премии, передача ссылок на эти сервисы, запуск worker. Подробный минимальный патч — `listener-integration.patch`.

Перед установкой сохранены исходный listener и Nginx-конфиг; каждый заменяется атомарно. Nginx сначала проверяется `nginx -t`, затем reload. После проверки кода требуется короткий restart `community-listener`, без удаления webhook или пропуска накопившихся апдейтов.

Откат модуля: восстановить прежний listener из серверной резервной папки и перезапустить сервис. `events.db` сохранять: повторная установка продолжит ту же очередь. Если нужно откатить маршрут API, восстановить Nginx-конфиг, проверить `nginx -t`, выполнить reload. Сайт откатывается отдельным Git-коммитом. Не восстанавливать старую общую `community.db`: она не менялась этой установкой и продолжает накапливать сообщения.

Проверка:

```sh
cd /opt/workspace/community-events-20261118/staging
/opt/bots/community-digest/venv/bin/python -m unittest -v test_events
```

Перенесены 16 существующих событий сообщества (включая архивные), перенесённый тур 19 ноября не добавляется. Для ещё не объявленных цен установлен `tba`, а не «бесплатно». Первичное наполнение **не** создаёт анонсов и не шлёт уведомлений.

Ограничения первого выпуска: анкета добавляет однодневное событие; многодневные события текущего плана импортированы как диапазоны. Изменение уже одобренной карточки — отмена и новая заявка с повторной модерацией. Оплата и регистрация на само мероприятие идут по ссылке организатора; календарь их не принимает. Состояние мини-приложения, подписки и правила остальных чатов не меняются.

Официальные ограничения: [Telegram Bot API](https://core.telegram.org/bots/api#getchatmember), [aiogram middleware](https://docs.aiogram.dev/en/latest/dispatcher/middlewares.html).
